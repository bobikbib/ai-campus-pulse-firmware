# Демо с веб-камерой ноутбука (без платы)

Сессии Infineon Live Lab не состоялись, поэтому показываем проект на ноутбуке:
веб-камера и микрофон заменяют камеру и микрофоны платы, а вместо платы работает
**тот же самый C-код** (`src/core`, `src/app`), собранный для ноутбука.

## 1. Что это и как устроено

Ноутбук = плата. Видео и звук обрабатываются прямо в браузере, на ноутбуке.
Из страницы уходят только числа (сколько людей, уровень шума, есть ли речь).
Картинка и звук никуда не отправляются и нигде не сохраняются.

```
Камера ─► браузер (sensor.html)           Микрофон ─► браузер
          модель EfficientDet-Lite0 int8              модель YAMNet
          считает людей                               шум + «речь/не речь»
                    │                                        │
                    └──────────── только числа ──────────────┘
                                         │  POST /api/frame
                                         ▼
                              Node-сервер (server/server.js)
                                         │  строки DET / AUD / TICK
                                         ▼
                              build/cp_cam  (C-ядро с платы:
                              таймер пустоты, протокол)
                                         │  строки CP>{json}
                                         ▼
                    Дашборд (http://localhost:8080/) ◄── опрос /api/rooms
```

Правило проекта остаётся прежним: 45 минут подряд пустая комната = бронь
освобождается. Дашборд показывает таймер «Пусто уже ММ:СС из 45:00».

## 2. Разовая настройка (Windows)

Python не нужен.

### 2.1. Node.js
Установите Node.js (версия LTS) с https://nodejs.org . Проверьте в терминале:
```bash
node --version
```

### 2.2. Компилятор C (w64devkit)
1. Откройте https://github.com/skeeto/w64devkit/releases и скачайте файл
   `w64devkit-x64-2.11.0.7z.exe` (это самораспаковывающийся архив).
2. Запустите его и распакуйте в `C:\Users\<имя>\w64devkit`
   (получится папка `C:\Users\<имя>\w64devkit\bin`).
3. В терминале **Git Bash** добавьте компилятор в PATH. Это действует только
   в текущем окне, при каждом новом окне команду нужно повторить:
   ```bash
   export PATH=/c/Users/<имя>/w64devkit/bin:$PATH
   gcc --version
   ```
   (вместо `<имя>` подставьте имя вашей папки пользователя.)

### 2.3. Сборка C-ядра
Из папки проекта:
```bash
make cam CC=gcc
```
Появится `build/cp_cam.exe`. Если после распаковки `make` не находится,
проверьте, что PATH из предыдущего шага выставлен в этом же окне.

### 2.4. Модели (нужен интернет, один раз, около 30 МБ)
```bash
bash tools/fetch_models.sh
```
Скрипт скачивает в `web/vendor/` библиотеки MediaPipe и в `web/models/` две модели
(`efficientdet_lite0.tflite` для людей и `yamnet.tflite` для голоса). Уже скачанные
файлы пропускаются, поэтому повторный запуск безопасен. После этого интернет
для демо не нужен.

## 3. Запуск

1. Запустите сервер (в папке проекта):
   ```bash
   node server/server.js
   ```
   Должна появиться строка `Campus Pulse server on http://localhost:8080`.
2. В **Chrome** или **Edge** откройте http://localhost:8080/sensor
   Это страница датчика. Адрес должен быть именно `localhost`: на других адресах
   браузер не даёт доступ к камере.
3. Введите номер комнаты (например `A-101`: латинские буквы, цифры, `-` и `_`,
   до 23 символов), нажмите **Старт** и разрешите доступ к камере и микрофону.
   Сначала загружаются модели, потом статус станет «Работает. Камера включена.»
4. В другой вкладке откройте дашборд: http://localhost:8080/

Остановить сервер: `Ctrl+C` в терминале.

### Дашборд с телефона
Запустите сервер так:
```bash
node server/server.js --lan
```
Телефон и ноутбук должны быть в одной сети Wi-Fi. На телефоне откройте
`http://<IP-ноутбука>:8080/` (IP смотрите командой `ipconfig`). Страницу датчика
(`/sensor`) при этом по-прежнему открывайте на самом ноутбуке по адресу
`localhost`. Если Windows спросит про доступ брандмауэра, разрешите для частной сети.
Сервер в режиме `--lan` слушает всю локальную сеть и не требует пароля,
используйте только в доверенной сети.

Другой порт: `node server/server.js --port 8090` (можно вместе с `--lan`).

## 4. Что вы увидите

**Страница датчика:** видео с зелёными рамками вокруг людей, число людей,
уровень шума, «речь слышна» / «тихо» и JSON, который уходит на сервер.

**Дашборд:** карточка комнаты:
- «Занято» и число людей, либо «Свободно» (тогда ниже полоса
  «Пусто уже ММ:СС из 45:00»);
- шум (число и полоска), голос («речь слышна» / «тихо» / «нет данных»);
- «Датчик недоступен», если данных нет (см. сценарий ниже);
- «обновлено N с назад».

## 5. Сценарий демо

1. Сядьте в кадр: через долю секунды карточка станет **«Занято»**, 1 чел.
2. Выйдите из кадра: комната остаётся «Занято» ещё около 10 секунд (защита
   от ложных срабатываний), затем становится **«Свободно»**, и начинает идти
   таймер «Пусто уже ...».
3. Вернитесь в кадр: «Занято», таймер сбрасывается.
4. Поговорите, пока комната пуста (например, из-за кадра): в карточке будет
   «речь слышна», шум вырастет, но комната **останется «Свободно»**, таймер
   не сбросится. Звук никогда не влияет на «занято/свободно» и на таймер.
5. Закройте вкладку датчика (или нажмите Ctrl+C у сервера, а страницу оставьте):
   через несколько секунд карточка покажет **«Датчик недоступен»**. Мёртвый
   датчик не считается пустой комнатой.

Важно про время: порог освобождения брони **45 минут реального времени**.
Ускоряющего режима в этой версии нет, поэтому для краткой демонстрации
показывайте, что таймер идёт («Пусто уже 00:40 из 45:00») и объясняйте,
что при 45:00 бронь была бы снята (при достижении порога карточка покажет
«бронь была бы снята»). Само ядро не изменяется.

## 6. Что отправляется (формат JSON)

Страница датчика шлёт на сервер (`POST /api/frame`, примерно 5 раз в секунду):
```json
{"room":"A-101","people":1,"noise_db":47,"voice":false}
```
Сервер передаёт числа в `cp_cam`, а тот печатает строки того же формата, что и
плата:
```
CP>{"v":1,"type":"presence","room":"A-101","people_count":1,"occupied":true,
    "empty_for_s":0,"sensor":"ok","mode":"camera","reason":"change",
    "uptime_s":120,"frames":2400,"noise_db":47,"voice":false}
```
Все сообщения дописываются в `data/readings.jsonl` (папка не попадает в git).

Новые поля:
- `noise_db`: **относительный** уровень шума 0..120. Это не откалиброванные
  децибелы, а условная шкала от громкости сигнала микрофона. Сравнивать можно
  «тише/громче» на одном и том же ноутбуке, но не с реальными дБ.
- `voice`: `true`, если модель услышала речь.
- Оба поля `null`, если свежих данных с микрофона нет (микрофон запрещён или
  модель голоса не загрузилась). Тогда шум и голос в дашборде «нет данных».
- Причина сообщения `"reason":"audio"` означает, что сообщение отправлено из-за
  изменения `voice`.
- **Звук не влияет на `occupied` и `empty_for_s`.** Они считаются только по камере.

## 7. Если что-то не работает

| Симптом | Причина и что делать |
|---------|----------------------|
| «Камера недоступна или доступ запрещён» | Браузер заблокировал камеру. Нажмите значок замка/камеры в адресной строке, разрешите, обновите страницу. Проверьте, что камеру не занимает другое приложение (Zoom, Teams) и что адрес именно `localhost`. |
| На странице сообщение про небезопасный адрес и кнопка Старт неактивна | Страница открыта не по `localhost` (например, по IP). Откройте `http://localhost:8080/sensor` на ноутбуке с камерой. |
| «Не удалось загрузить модель камеры» | Не скачаны модели. Выполните `bash tools/fetch_models.sh`. |
| «камера не даёт кадров, данные не отправляются» | Камера отключилась или завис поток. Данные намеренно не шлются, чтобы не показывать устаревшее число людей. Переподключите камеру или обновите страницу и нажмите Старт. Дашборд тем временем покажет «Датчик недоступен». |
| «сервер не отвечает (повторяю...)» | Сервер остановлен или это другой порт. Запустите `node server/server.js`, проверьте адрес и порт. |
| «сервер отклонил данные: ...» | Сервер вернул ошибку 400, чаще всего из-за неверного имени комнаты. Используйте латиницу, цифры, `-`, `_`. |
| «микрофон недоступен» | Доступ к микрофону запрещён. Камера и подсчёт людей при этом работают, шум и голос показываются как «нет данных». |
| Страница датчика «Работает», но на дашборде нет карточки комнаты | Не собран `build/cp_cam.exe`. Сервер отвечает 200 на кадры, но они теряются; в терминале сервера будет строка `cp_cam[<комната>] error: spawn ... ENOENT`. Выполните `make cam CC=gcc` (с PATH из п. 2.2) и перезапустите сервер. |
| `fetch_models.sh`: ошибка curl / «empty download» | Нет интернета или он блокирует `cdn.jsdelivr.net` и `storage.googleapis.com`. Проверьте сеть и запустите скрипт ещё раз: готовые файлы пропускаются, докачается остальное. Запускайте через `bash` (Git Bash). |
| `make: gcc: not found` / `make: command not found` | Не добавлен w64devkit в PATH в этом окне Git Bash: `export PATH=/c/Users/<имя>/w64devkit/bin:$PATH`. |
| Сервер: `EADDRINUSE` (порт занят) | Порт 8080 занят. Закройте другую программу или запустите на другом порту: `node server/server.js --port 8090`, и открывайте `http://localhost:8090/...`. |

## 8. Перенос на плату

**Не меняется** (тот же код, что в демо): `src/core` и `src/app`: подсчёт «занято/
пусто», таймер, протокол, `cp_app_on_audio()`. На ноутбуке они проверены тестами
и работой `cp_cam`.

**Меняется:**
- Детектор людей: вместо браузерной модели считает YOLACT из примера
  `aihub-deploy-vision` (через существующий патч `tools/apply_to_example.sh`),
  результат уходит в `cp_app_on_detection()`.
- Звук: микрофоны платы должны вызывать `cp_app_on_audio(noise_db, voice, now_ms)`
  (объявлена в `src/app/cp_app.h`). Эта часть для платы **не написана**.
- Вывод: строки `CP>` идут в UART платы, а не на stdout `cp_cam`.

**Не проверено:** сборка и работа на плате (порт под PSOC Edge ни разу не
собирался с настоящим SDK), качество подсчёта YOLACT на плате, звук на плате.
Модели браузера (EfficientDet-Lite0, YAMNet) на плату не переносятся.
