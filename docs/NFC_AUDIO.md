# Звук и NFC на плате

Вся обработка идёт **на плате**. Телефон и ноутбук только доставляют сигналы.

```
 микрофон платы ─► audio.c: уровень дБ + «говорят ли» (каждые 100 мс)
 камера платы   ─► presence.c: люди, занято/пусто
                        │
 телефон (NFC) ─скан─► шлюз ─"NFC <uid>"─► плата: камера увидела человека за 10 с?
                        ▲                        │ да → entry confirmed
                        └── CP>{"type":"entry"} ─┘ нет → entry rejected (в базу ничего)
                        │
                        ▼ только подтверждённые
                 Supabase: record_nfc_scan (посещение)
                 Supabase: ingest_board (люди, пусто, noise_db, voice)
```

## Что считает плата

**Звук** (`src/core/audio.c`): берёт 16-битный звук 16 кГц окнами по 100 мс.
- `noise_db`: громкость в дБ SPL (`dBFS + 120` для типичного цифрового
  микрофона −26 dBFS @ 94 дБ SPL). За интервал отчёта (5 с) усредняется по энергии,
  поэтому громкие моменты не теряются.
- `voice`: окно громче фонового шума минимум на 8 дБ **и** редко пересекает ноль
  (голос ~80–400 Гц), в отличие от шипения или вентилятора. Если голос был
  в ≥10% окон за интервал, в отчёте `voice: true`.
- С платы уходят **только эти два числа**. Звук не записывается и не передаётся.

**Уровень шума** (`cp_noise_classify` в `protocol.c`): плата сама выбирает категорию,
поле `noise_level` в отчёте:

| `noise_level` | Условие | По-русски |
|---|---|---|
| `too_loud` | ≥ 70 дБ | слишком шумно |
| `noisy` | 50–70 дБ | шумно |
| `quiet` | < 50 дБ, но камера видит людей или кто-то говорит | тихо |
| `empty` | < 50 дБ, никого на камере, никто не говорит | никого нет |

Обратно в более тихую категорию плата переходит только на 3 дБ ниже порога, чтобы
значение не прыгало. Пороги задаются в `cp_config.h`: `CP_NOISE_QUIET_MAX`,
`CP_NOISE_LOUD_MIN`, `CP_NOISE_HYSTERESIS_DB`. В базе это колонка `noise_level`
в `v_room_status` (миграция `20261128000600_noise_level.sql`).

**NFC** (`cp_app.c`): команда `NFC <uid>` (4–20 hex-символов) ставит скан в ожидание.
- Камера увидела ≥1 человека за 10 с (`CP_NFC_CONFIRM_MS`): `entry` с `"confirmed":true, "reason":"person_seen"`.
- Никого: `"confirmed":false, "reason":"nobody_seen"`.
- Камера не работает: `"camera_unavailable"` (такой скан никогда не подтверждается).
- Новый скан до решения по старому: старый получает `"replaced"`.

Новые строки платы:
```
CP>{"v":1,"type":"presence",...,"noise_db":55,"voice":false,"noise_level":"noisy"}
CP>{"v":1,"type":"entry","room":"Z-3-03","card":"04A1B2C3","confirmed":true,"reason":"person_seen","people_count":1,"wait_ms":110,"uptime_s":15}
```

## Камера спит, когда ничего не происходит

Камера не смотрит постоянно (`cp_app.c`, параметры в `cp_config.h`):
- **active**: анализируется каждый кадр. Так бывает, пока в комнате есть люди, ждёт
  NFC-скан, слышен голос или шум ≥ 50 дБ (`CP_CAM_WAKE_DB`).
- **asleep**: если 30 с (`CP_CAM_HOLD_MS`) ничего этого нет, анализируется **один кадр
  в 15 с** (`CP_CAM_SLEEP_PERIOD_MS`). Этого хватает для правила 45 минут и чтобы заметить
  человека, который сидит молча. Человек на таком кадре, звук или NFC-скан будят камеру сразу.
- Микрофон слушает всегда, но наружу уходят только уровень и «есть голос».
- Пока камера спит, редкие кадры не считаются поломкой датчика (`stale` не наступает).
- В отчёте платы есть поле `"camera":"active"|"asleep"`, а сайт показывает
  «Camera active» (зелёная точка) или «Camera asleep».

На плате это делает `cp_port_frame_gate()`: её вызывает цикл ИИ после каждого кадра
(вставляет `apply_to_example.sh`). Пока камера спит, цикл ждёт, и ни камера, ни модель
не работают зря.

**Прозрачность (GDPR / австрийский DSG):** у двери комнаты нужна табличка о датчике
с камерой, а на сайте при бронировании показывается строка о датчике. Изображения и звук
не покидают устройство. Перед реальным запуском это нужно согласовать
с Datenschutzbeauftragte университета.

## Демо на симуляторе (плата недоступна)

Симулятор запускает тот же C-код. Звук он синтезирует (фон + «голос» со слогами)
и прогоняет через тот же анализатор, что и на плате.

```bash
cd ~/ai-campus-pulse/campus-pulse-firmware && make
export SUPABASE_KEY='sb_publishable_...'
python3 bridge/board_gateway.py --supabase https://<project>.supabase.co --room Z-3-03
```
Команды в том же окне: `SIM 1` / `SIM 0` (люди), `NOISE 65` (шум, дБ), `VOICE 1` / `VOICE 0` (разговор).

**Телефон** (Pixel по USB, приложение из `android-nfc-reader`):
```bash
~/Library/Android/sdk/platform-tools/adb reverse tcp:8090 tcp:8090
```
В приложении: **Supabase URL** = `http://127.0.0.1:8090`, остальные поля как раньше
(anon key, Reader ID, Reader secret) → Save. Приложите карту:
- в комнате кто-то есть (`SIM 1`): «Entry confirmed by the board (Z-3-03): имя», запись в базе;
- никого (`SIM 0`): через 10 с «Entry not confirmed by the board…», в базу ничего.

## На настоящей плате: что не проверено

- **Микрофон.** Пример с камерой (`aihub-deploy-vision`) не включает микрофон. Нужно
  добавить PDM-драйвер (16 кГц, 16 бит, моно) из примера Infineon с PDM/PCM-аудио и в его
  задаче вызывать `cp_port_on_audio(pcm, n)`. Пока этого нет, поля `noise_db`/`voice`
  просто не отправляются, и база пишет NULL.
- **Ввод команд в плату.** Порт читает команды из RX-FIFO отладочного UART
  (`Cy_SCB_UART_Get`). Принимает ли консоль Live Lab ввод, неизвестно.
- `log10f`, `powf`, `sinf` из libm. Если линковщик скажет `undefined reference to log10f`,
  добавьте `-lm` в `LDLIBS` Makefile примера.
- Код проверен: 99 тестов на ноутбуке (ASan/UBSan) и компиляция под Cortex-M55 без предупреждений.
  Размер: ~5,4 КБ кода, ~5 КБ RAM (из них 4 КБ стек задачи), куча 0 Б.
